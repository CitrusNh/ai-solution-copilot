# 项目经历与作品集材料

## 简历标题

**AI 企业研究与售前方案助手｜独立项目｜Python、Streamlit、RAG、OCR、OpenAI 兼容 API**

## 简历描述

- 面向 B2B AI/SaaS 售前场景，完成从用户问题、PRD、资料上传到公网部署的 MVP；支持 MD/TXT/PDF 与扫描件 OCR，以字符级 TF-IDF 和意图加权检索内部资料并保留文件、章节和页码来源。
- 设计“内部证据 D / 互联网资料 W / AI 生成内容”三层信息边界，接入按需联网搜索和结构化聊天模型接口；对 BYOK、等保、数据驻留等未承诺需求强制人工确认，外部服务异常时降级到本地规则结果。
- 建立 10 道冻结评测集和 39 项自动化测试，开发集 10/10 通过；完成真实联网、扫描 PDF OCR 与聊天模型冒烟测试，并通过 GitHub 和 Streamlit Cloud 提供公开 Demo。

## 面试展开版

售前人员回答价格、部署、安全和功能问题时，需要同时查多份资料。我的产品不是一个泛聊天机器人，而是先检索内部产品证据，再输出匹配能力、限制风险、追问和回复草稿。资料没有承诺 BYOK 或等保时，系统明确提示不能承诺并转人工确认。

第一版先做零 API 成本的本地规则基线，冻结 Top-1、Top-3、置信状态和关键风险题指标。MVP 1.0 再加入三个能力：扫描 PDF 使用 PyMuPDF 渲染和 RapidOCR 本地识别；联网搜索只发送客户问题并与内部资料分区；聊天模型通过 OpenAI 兼容接口输出固定 JSON，程序校验证据编号与人工确认边界，失败时保留本地结果。

这体现的不只是代码实现，也包括用户场景选择、产品边界、风险控制、评测设计、成本意识和公开交付。下一阶段需要真实目标用户测试，记录任务用时、人工修改率和有用性评分。

## 量化结果的正确表述

- “10/10 通过”指项目内冻结的 10 道开发评测题，不等于真实客户准确率。
- “39 项测试通过”指本地自动化测试，不等于生产环境稳定性证明。
- “真实 OCR/联网冒烟通过”表示核心路径实际运行成功，不代表所有文件和网络环境都不会失败。
- 聊天集成完成了代码、模拟兼容 API 测试、引用校验和失败降级，并已在公网用 APINebula `deepseek-v4-flash` 验证价格题与 BYOK 风险题；这属于冒烟测试，不等于全量质量验证。
- 公网 Demo 没有登录、权限、持久化或多租户能力，不支持企业机密资料。
- 真实用户反馈目前仍待收集，面试时应主动说明这一限制和验证计划。
