# AI 企业研究与售前方案助手 PRD

## 1. 产品定位

面向 B2B AI/SaaS 公司的初级售前、解决方案顾问和产品运营，帮助他们从分散的产品资料与公开信息中快速形成可核验的客户需求分析和售前回复草稿。

## 2. 核心用户问题

- 产品资料分散在说明书、价格表、安全 FAQ 和扫描文件中，查找耗时。
- 客户需求难以快速映射到产品能力，非资深售前容易遗漏限制条件。
- 大模型可能把公开资料或常识误当成本企业已承诺能力。
- 回复缺少来源，难以复核、交接和追责。

## 3. MVP 1.0 用户流程

1. 用户上传 MD、TXT、普通 PDF 或扫描版 PDF 产品资料。
2. 系统解析、OCR、切分并保留文件名、章节或页码。
3. 用户输入客户问题，并按需开启联网搜索或聊天模型增强。
4. 系统检索 Top-3 内部证据并生成本地规则安全基线。
5. 可选聊天模型根据内部证据和公开资料优化分析与回复表达。
6. 页面分区展示内部证据、互联网公开资料和模型输出。
7. 用户下载 Markdown 报告并提交有用性反馈。

## 4. 输出结构

- 客户需求摘要与置信状态
- 已确认的产品匹配能力
- 限制、风险与能力缺口
- 建议继续询问客户的问题
- 本地规则售前回复草稿
- 可选 AI 增强分析与回复草稿
- 内部证据和互联网来源
- Token 使用量与模型名（启用聊天时）

## 5. 核心规则

- 只有内部资料可以证明本产品能力。
- 互联网资料只能补充背景，必须与内部证据分区展示。
- 资料未承诺 BYOK、等保、数据驻留等能力时，必须转人工确认。
- 聊天模型失败或输出不合规时，保留本地规则结果。
- 联网搜索默认关闭，且不发送上传文档。
- 聊天增强默认关闭，启用前明确提示数据会发送给模型服务商。

## 6. 非功能要求

- 单文件不超过 10MB，单个 PDF 最多 OCR 20 个扫描页。
- 外部 API 设置明确超时和有限重试，失败不阻塞核心本地分析。
- API Key 仅从环境变量或部署 Secrets 读取。
- 用户上传、反馈、缓存和密钥不得提交到 Git。
- 每次改动需配套自动化测试并通过冻结评测。

## 7. 当前不做

登录、多租户权限、计费系统、云端持久化、企业级审计、模型微调、语音和自动对外发送销售消息。

## 8. 成功指标

当前开发验证：

- 10 道冻结开发评测题严格通过率 100%。
- Top-3 来源命中、Top-1 来源、置信状态和关键风险题均通过。
- 33 项自动化测试通过。
- 真实联网和扫描 PDF OCR 冒烟测试通过。

下一阶段产品验证目标：

- 至少 3 名目标用户独立完成任务测试。
- 扩展到 20 道以上独立测试题，关键风险题保持 100%。
- 记录任务完成时间、人工修改率、有用性评分、模型成本与失败率。
- 聊天增强只有在质量提升且成本/延迟可接受时才默认推荐。
