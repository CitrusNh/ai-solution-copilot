## 反馈主题

### 测试记录 001

- 日期：2026-08-31
- 测试者：项目发起人
- 任务：查询“是否支持 BYOK？”并检查系统是否会作出无依据承诺。
- 正确表现：系统显示“资料不足，需要人工确认”，没有宣称支持 BYOK。
- 发现问题：匹配能力仍展示与 BYOK 无关的通用产品功能；回复草稿出现“。；”机械拼接；证据区域标题重复。
- 产品结论：当检索证据包含“没有承诺、需要人工确认、不得推断”等阻断信息时，普通产品介绍不能作为该需求的匹配能力展示。
- 迭代动作：加入阻断风险规则和回归测试，清理输出格式。

### 测试记录 002

- 日期：2026-08-31
- 测试者：项目发起人
- 任务：复测 BYOK 阻断场景并粘贴完整页面结果。
- 正确表现：不再展示无关匹配能力，回复标点和证据标题已修复。
- 发现问题：上传控件显示“200MB per file”，但产品解析规则实际限制单文件 10MB。
- 产品结论：界面展示的输入限制必须与后端校验一致，否则会造成无效上传和用户困惑。
- 迭代动作：增加 Streamlit 配置，将上传控件限制同步为 10MB。

### 测试记录 003

- 日期：2026-08-31
- 测试者：开发者代理进行页面回归，项目发起人负责确认产品方向。
- 任务：分别查询“私有化部署怎么收费？”“最多支持多少用户？”和“是否支持 BYOK？”。
- 正确表现：用户上限返回价格资料，BYOK 保持转人工，私有化部署明确需要单独评估。
- 发现问题：用户上限结果夹带无关权限能力；私有化收费虽然命中正确证据，但置信表达容易被理解为系统完全无法回答；结果缺少下载和反馈入口。
- 产品结论：检索命中不等于答案可用，还需在句子层面过滤无关内容；“有明确的限制型答案”应与“资料完全未知”区分；作品集需要形成测试与迭代闭环。
- 迭代动作：加入意图加权、句子相关性过滤、Markdown报告下载和本地反馈记录。
