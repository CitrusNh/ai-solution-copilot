# 2～3 分钟演示脚本

## 开场（约 20 秒）

“这是一个 AI 企业研究与售前方案助手。它服务 B2B AI/SaaS 公司的售前、解决方案顾问和产品运营，目标不是泛泛聊天，而是把客户问题和产品资料连接起来，输出可以复核的售前结论。”

## 场景一：明确事实（约 45 秒）

1. 打开公网 Demo 或本地页面。
2. 在问题框输入：`最多支持多少用户？`
3. 点击“生成售前分析卡”。
4. 指出页面中的：`SaaS 专业版最多 500 名用户`、来源文件 `pricing_and_limits.md`、限制和追问清单。
5. 点击“下载 Markdown 分析报告”，说明结果可以交接给同事或留档。

讲解重点：系统不仅回答数字，还把证据来源、限制条件和下一步沟通问题一起给出来。

## 场景二：未知安全需求（约 50 秒）

1. 输入：`是否支持 BYOK？`
2. 展示状态：`资料不足，需要人工确认`。
3. 指出系统不会把“支持 PDF、网页问答”等通用能力误当成 BYOK 支持。
4. 展示风险提示：资料没有承诺 BYOK，不能自行推断。

讲解重点：售前场景中，拒绝无依据承诺和明确升级人工，可能比生成更肯定的答案更有价值。

## 场景三：解释实现与验证（约 45 秒）

“当前 MVP 使用字符级 TF-IDF 和业务意图加权，中文不依赖分词，结果容易解释；文档按章节/页切分并保留来源。项目另外准备了 Embedding 客户端和混合检索实验，但只有在同一评测集证明收益后才考虑接入。当前 10 道开发评测题 10/10 通过，26 项自动化测试通过，规则版本 API 成本为 0。”

## 收尾（约 20 秒）

“下一步会用真实售前或产品用户完成任务测试，记录有用性、错误承诺风险和节省的查找时间，再决定是否接入大模型和云端多用户能力。”
